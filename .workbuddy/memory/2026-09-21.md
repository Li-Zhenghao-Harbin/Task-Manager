## 004 界面细节修订

- 产出规格：`specs/004-ui-refinements/{spec.md, design.md, tasks.md}`，截图在 `screenshots/`。**本次只改前端，Go 零改动。**
- **移除保存状态胶囊**：删掉 `saveState`/`saveHint` ref 与 `saveStateText`，`flushSaves()` 校验失败改为 `message.value = issue`
  （与其它错误统一出口）。即时保存行为未变，只是不再常驻显示。副作用：校验失败提示 3 秒后消失。
- **列表分组重构**：模板里原来内联的三段过滤（父行 + 子行 + 悬空子行）改成两个 computed：
  `taskGroups`（父任务命中筛选，**或父任务未命中但有子任务命中 → `context:true`**）、`orphanChildren`（父任务已删除）。
  这是「筛进行中时要看到已完成上级」的实现方式。`orphanChildren` 判据从「父不在 filteredTasks 里」收紧为「父在 tasks 里找不到」。
  样式：`.task-row.context` 用 `::before` 画左侧色条（**不用 border-left，否则整行内容右推 3px 与其它行错位**），
  且刻意不覆盖 `background`，保留 `.completed` 的绿底作为「它已完成」的信息。
- **「5小时后可用」快捷键**：`setAgentCooldown(target, hours)` 输出 `YYYY-MM-DDTHH:mm` **本地时间**
  （必须对齐后端 `agentResetLayout`；用 `toISOString()` 会得到 UTC + 秒，语义不符），并置 `available=false`。
  只改这两个字段 → 复用既有 deep watch → `queueAgent` → `UpdateAgentApp` 链路，无需新接口。
  **按钮必须放在 `.agent-project-item` 那类 `<label>` 之外**：label 内嵌 button 属无效交互式嵌套，点击会顺带激活 label 的 checkbox。
- 验证：mock 预览页 + Chrome 无头截图四视图，行为断言横幅全绿（含「距点击 300 分钟」「save-state 元素=0」「context 紧邻子任务上方」）。

## 005 Agent 关联任务的 Prompt 管理

- 产出规格：`specs/005-agent-task-prompts/{spec.md, design.md, tasks.md}`，截图在 `screenshots/`（5 张，含空态）。
- 需求澄清结论：prompt 是**纯文本**（无标题/备注）；**解除关联时保留** prompt；prompt 列表显示在**右侧详情面板**；
  Agent 列表行**点一下 = 选中并展开**（再点收起）。
- 后端 `app.go`：新增 `AgentPrompt{ID,Text}` 与 `AgentApp.Prompts map[taskID][]AgentPrompt`（存在 Agent 上，键是任务 ID，
  语义是「用这个 Agent 跑这个任务」）。接口只有两个：`ListAgentPrompts` / `UpdateAgentPrompts`（**整体替换**，
  与右侧面板的即时保存模型一致，加/删/改在前端都是对本地列表的操作）。
  `normalizePrompts` 丢纯空白条目、补空 ID、按 rune 截断到 20000、上限 50 条（**超限截断而非报错**，避免粘贴长文直接失败）。
  `validatePromptTargetLocked` 要求「Agent 存在 + 任务已关联到它 + 类型为 code」。
  生命周期：`DeleteTask` 清掉各 Agent 下该任务的 prompt；`load`/`ImportData` 走 `normalizeAgentPromptsLocked()`（nil→空 map、
  剪掉指向不存在任务的键）；`UpdateAgentApp` 靠「复制结构再改字段」天然不动 prompt。
- 前端 `App.vue`：`expandedAgentIds` + `selectedAgentTaskId` + `selectedAgentTask`(computed)。
  **`selectedAgentTask` 里校验 `agent.projectIds.includes(taskId)`**，这一条同时兜住了「取消关联后面板停在已解除任务上」，
  不需要额外清理代码。prompt 走独立的 `prompts` ref + `savedPromptSignature`：签名基于**过滤掉空条目**的 payload，
  所以点「添加」不发请求、而**把已有内容清空会真的触发保存让后端删掉那条**。落盘后写回 `agent.prompts[taskId]` 并把本地空草稿留在末尾。
- 测试从 19 项增至 **29 项**（新增 `prompt_test.go` 10 项：往返/空白丢弃/ID 补全去重/目标校验/删任务清理/解除关联保留/
  `UpdateAgentApp` 不动 prompt/上限/旧存档无 prompts 字段/孤儿键剪除）。
- 界面验证：mock 预览 5 视图，行为断言横幅全绿（展开得 2 个任务行且计数正确；添加后**保存次数 0**、输入后 payload 3 条无空条目；
  删除后 payload 1 条；空态文案与「只展开 TRAE」）。
