# 011 · Agent 列表：可用时不显示「下次可用时间」

> 本规格**修订 010 的验收标准第 2 条**（010 当时要求可用时该列显示 `下次可用时间：—`）。

## 背景

010 给 Agent 列表行的日期列加了「下次可用时间：」前缀，并把可用时的取值定为 `—`，
当时的理由是「保持这一列始终有说明文字」，避免出现一个没有说明的裸日期。

实际使用后这个理由不成立：**应用当前可用时，这一格不携带任何信息**——
「现在可用」这件事行尾的「可用」标签已经说过了，而「下次可用时间」在可用状态下本就无意义。
`下次可用时间：—` 只是让人多扫一个空字段，行内信息密度反而变低。

Agent 详情面板里同一个字段早就是「只在不可用时出现」（`v-if="!selectedAgent.available"`），
列表行与此统一，两处规则一致后也不必再解释为什么写法不同。

## 做什么

### 1. 列表行：可用时整格不渲染

- `.agent-reset` 那一格加 `v-if="!agent.available"`：**应用可用时该元素不存在**，
  不再显示 `下次可用时间：—`。
- 应用不可用时行为不变：`下次可用时间：<格式化日期>`（未设置时沿用 `未设置`）。
- 行内其余三项（展开指示符 / 应用名-模型名 / 可用情况标签）完全不变。

### 2. 栅格列数跟随可见子元素

- 可用行只有 3 个子元素，需要 3 列；不可用行（宽屏）有 4 个子元素，需要 4 列。
  每行自己是独立的 grid 容器，**多一列会把末项挤到第二排**（010 已踩过）。
- 实现：行上按可用与否加 `.available` 类，`.agent-row.available{grid-template-columns:16px minmax(0,1fr) 78px}`。
- 窄屏断点（`max-width:1100px`）把日期列整列隐藏、栅格降为 3 列，
  该断点的规则里要**显式带上 `.agent-row.available`**——媒体查询不增加特异性，
  否则窄屏下更高特异性的 `.agent-row.available` 会盖掉断点里的列定义。

## 不做什么

- 不给可用行留空白占位格（**刻意不占位**）：可用行让「应用名-模型名」列吃满释放出来的宽度。
- 不动 Agent 详情面板的字段（它本来就只在不可用时出现），也不动「新增 Agent 应用」弹窗。
- 不动可用情况标签的文案与配色，不动行的展开/收起、选中态、点击行为。
- 不改 `AgentApp.resetAt` 字段名与后端逻辑；`resetText()` 仍被不可用行使用，保留。
- 不改 `.agent-pill` 的固定 78px 列宽，也不改 1100px 这个断点值。

## 验收标准

1. 应用可用的行内**不含**「下次可用时间」字样、不含 `—`；`.agent-reset` 元素数量等于不可用 Agent 的数量。
2. 应用不可用的行内文本为 `下次可用时间：<日期>`（未设置为 `未设置`）。
3. 可用行可见子元素 3 个、栅格 3 列（计算值）；不可用行（宽屏）可见子元素 4 个、栅格 4 列。
4. **混排对齐**：同一列表中可用行与不可用行的「应用名-模型名」左边缘、「可用情况」标签右边缘分别对齐（差值 ≤ 1px）——
   这是列数没写错的直接证据。
5. `gofmt` / `go vet` / `go test ./...` / `vue-tsc` / `wails build` 全部通过，无回归。
