# 004 界面细节修订规格

> 本规格承接 `specs/003-live-save-and-reset-notify/`，只做界面层与交互的小幅修订，不动数据模型。

## 背景

003 把右侧面板改成即时保存后，面板标题处常驻了一个保存状态胶囊（「修改即时生效 / 已自动保存 / 正在保存…」）。
实际使用下来这个胶囊没有信息价值——保存是无感的，常驻提示反而占据标题区、和状态徽标挤在一起。

同时发现两处可用性缺口：

1. **筛「进行中」时子任务会失去上级线索**。任务列表按「上级任务 → 子任务」两级渲染，上级任务若不满足当前筛选条件
   （例如已完成后被筛掉），它的子任务就被降级成列表末尾的悬空项，看不出归属。
2. **把 Agent 置为不可用需要两步手工操作**：取消勾选「当前可用」，再手填一个重置时间。而最常见的诉求是
   「这个额度用完了，过 N 小时再试」，值得给一个一键入口。

## 做什么

### 1. 移除右侧面板的保存状态提示

- 删除任务详情面板与 Agent 详情面板标题区的保存状态胶囊（`.save-state`）。
- **即时保存行为本身不变**：改动仍然防抖 500ms 自动落盘，仍不做「保存」按钮。
- 校验未过或落盘失败时，改走应用既有的底部 toast 提示（与其它错误一致的出口），面板内不再有常驻提示。

### 2. 列表为子任务补齐上级任务

- 任务列表改为「分组」渲染：上级任务作为分组头，其子任务缩进列在下面。
- 一个上级任务满足以下任一条件即成为分组头：
  1. 它本身满足当前筛选条件；
  2. 它本身不满足筛选条件，但至少有一个子任务满足（**这类分组头标记为 context**）。
- context 分组头用暗色文字 + 左侧色条标出，且**保留其真实状态徽标**（例如「已完成」），
  让人一眼看懂「它是作为上级被带出来的，不是筛选命中的」。
- 子任务仍只在满足筛选条件时显示；上级被删除（`parentId` 悬空）的子任务单独列在最后，文案标注「子任务（上级已删除）」。

### 3. Agent 详情面板增加「5小时后可用」快捷按钮

- 位置：`可用情况` 下方的独立一行，位于 `下次重置时间` 字段之前。
- 行为：点击后立刻把该 Agent 置为不可用，并把「下次重置时间」设为**当前时间 + 5 小时**（分钟精度）。
- 两个字段都是 Agent 自身的可编辑字段，因此仍走同一条即时保存链路，无需额外接口。
- 置为不可用后，「下次重置时间」字段自动出现并回填该值，用户仍可手工改成别的时间。
- 到点后由 003 的常驻检查恢复可用并发送 Windows 通知，本次不新增通知逻辑。

## 不做什么

- 不改 `Task` / `AgentApp` 的数据结构与 Go 接口（无字段增删、无新接口）。
- 不做冷却时长的配置化（固定 5 小时；需要别的时长可点按钮后手工改时间）。
- 不改创建 Agent 的模态框（只改详情面板）。
- 不改产出页、日历视图、单位管理。
- 不改 003 确立的「`Task.AgentID` 为唯一事实来源」关联模型。
- 不改自动保存的防抖时长与签名防回环机制。

## 验收标准

1. 任务详情面板与 Agent 详情面板的标题区都不再出现保存状态胶囊；面板里没有「保存」按钮。
2. 面板里改任一字段后仍会自动落盘（行为未回退）。
3. 面板把必填字段清空时不发保存请求，且底部弹出一次错误提示。
4. 在「进行中」筛选中，若某子任务满足条件而其上级已完成，则该上级作为分组头显示在子任务正上方，并带「已完成」徽标。
5. 该上级分组头在视觉上可区分（暗色文字 + 左侧色条），且不影响「全部任务」等其它筛选下的正常显示。
6. 上级被删除的子任务仍能显示，不会被漏掉。
7. Agent 详情面板「可用情况」下方存在「5小时后可用」按钮。
8. 点击该按钮后：Agent 变为不可用、`resetAt` 为点击时刻 + 5 小时且精确到分钟、面板出现「下次重置时间」字段并回填该值。
9. 该次变更通过即时保存链路落盘（`UpdateAgentApp` 收到 `available=false` 与对应 `resetAt`）。
10. `gofmt` / `go vet` / `go test ./...` / `vue-tsc` / `wails build` 全部通过。
