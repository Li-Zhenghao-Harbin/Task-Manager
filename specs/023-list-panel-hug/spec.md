# 023 列表卡片一律贴合内容（Agent应用 / 单位管理 / 产出概览·任务列表）

> 修订 [022](../022-output-panel-hug/spec.md)：022 只改了「有富余空间也不长高」（`flex-grow:0`），
> 漏了两件事 —— ① 卡片自己的 `min-height` 下限会把**短**列表撑高；② Agent / 单位两个面板压根没动。
> 用户反馈：「【AGENT应用】菜单和【实施】菜单中的仍然没有改」。

## 背景

022 之后【产出概览】的**代码 / 文档**两个筛选已经贴合内容（卡片高 475/483，内容 474/482），
但用户点开【实施】和【AGENT应用】仍看到大片空白。用探针量出来的原因分两种，都不是 022 那条改动的事：

| 视图 | 022 之后的实际读数（1440x900 / 1920x1040） | 用户看到的 |
| --- | --- | --- |
| 产出概览·实施 | 卡片 200 / 内容 132，**卡片内部空白 68px** | 卡片里挂着一条白 |
| Agent应用 | 面板 789 / 内容 634，**卡片内部空白 147px**；卡片外留白 0 | 列表被拉到满屏 |
| 单位管理 | 面板 789 / 内容 147，**卡片内部空白 620px**；卡片外留白 0 | 同上 |

- 【实施】是**下限**问题：`.chart-panel,.output-list` 共用一条 `min-height:200px`，这道下限本来是给
  饼图卡片防压扁的，对只有一个任务的短列表却成了「撑高」。
- 【Agent应用】/【单位管理】是**没改**问题：它们还是 021 之前的 `flex:1 1 auto`。

022 的探针只量了「卡片**外**的留白」（`freeBelow`），所以这三种情况全部通过 —— 判据缺了一条：
**卡片内部**也不许留空白。

## 做什么

`frontend/src/App.css` 末尾「滚动归属」一节，两处改动：

| # | 选择器 | 之前（022） | 之后（023） |
| --- | --- | --- | --- |
| 1 | `.output-list` | `flex:0 1 auto` + `min-height:200px` | `flex:0 1 auto` + **`min-height:0`** |
| 2 | `.agents-panel`、`.units-panel` | **`flex:1 1 auto`** + `min-height:0` | **`flex:0 1 auto`** + `min-height:0` |

改完这两处，三张「列表卡」（`.output-list` / `.agents-panel` / `.units-panel`）与【全部任务】的
`.task-list` 成为**逐字相同**的一套声明：

```css
.output-list,.agents-panel,.units-panel{flex:0 1 auto;min-height:0;overflow-y:auto;overscroll-behavior:contain}
```

`.chart-panel` 单独一条，保留 `min-height:200px`（它是唯一内容尺寸固定的卡片：310px 的饼图）。

## 不做什么

- **不动 `App.vue`**：全是 CSS 声明改动，没有模板/逻辑变化（产物 JS 哈希不变可作为佐证）。
- **不动 `.task-list` / `.calendar-scroll` / `.prompt-board`**：它们是参照物，本身已经是对的。
- **不删 `.chart-panel` 的 `min-height:200px`**：1024x680 下 `.output-body` 只有 429px、
  KPI 卡片行占 405px，摘掉下限饼图卡片会被压到 38px（看不到也点不到）。
- **不改单位管理之外的其它样式**：`.units-panel` 的 `padding:22px`、`.agents-panel` 的 `padding:8px` 都不动。

## 验收标准

1. **同一套声明**：三张列表卡的 computed `flex` 与 `min-height` 逐项等于 `.task-list` 的**声明值**
   （`0 1 auto` / `0px`）—— 比对的是「卡片 ↔ 参照物」，不是「参照物 ↔ 字面量」（022 踩过：那样等于自证）。
2. **贴合**：内容装得下时，卡片高 == 内容高，**卡片内部**空白 ≤ 1px（只剩 1px 下边框），
   多出来的空间留在卡片**外**。
3. **吃满**：内容装不下时，卡片吃满可用高度（卡片外留白 ≤ 1px），滚动条长在卡片自己的
   `overflow-y` 上，能滚到末尾。
4. **页头固定 / 整区不滚**：沿用 019–021 的口径（`.workspace` 不溢出且 `overflow-y:hidden`，
   滚动前后页头 `top` 不变）。
5. **饼图卡片下限仍在**：`.chart-panel` computed `min-height` == `200px`，1024x680 下实测高 200（未被压扁）。
6. **对照组必须翻红**：
   - 注入 022 的 `.output-list{min-height:200px}` → 【实施】卡片内空白回到 68px，至少 2 条断言失败；
   - 注入 021 的 `flex:1 1 auto` → Agent / 单位面板内空白回到 147 / 620px，至少 2 条断言失败；
   - 注入 020 的「滚动挂 `.output-body`」→ 021 的判据仍要翻红（旧证据不能丢）。
7. **参照物自证**：【全部任务】自己也跑同一组判据（长列表时吃满 + 内部滚动），全部通过。

## 影响面与兜底

- 卡片贴合后不会再「吃掉」富余空间，因此低于约 780px 高的窗口里【产出概览·全部产出】
  由 `.output-body` 兜底滚动的行为**不变**（卡片行 405 + gap 22 + 饼图下限 200 = 627，
  加上 `.workspace` 内边距与页头的 153px）。代码 / 文档 / 实施三个筛选的卡片行只有 125px，
  列表自己会压缩，兜底基本用不到。
- `.agents-panel` / `.units-panel` 贴合后，Agent 列表或单位列表很长时由面板自己的 `overflow-y`
  出滚动条（与【全部任务】一致）；窗口高 522（1440x620）时实测面板压到 369、内部溢出 273，滚动正常。
