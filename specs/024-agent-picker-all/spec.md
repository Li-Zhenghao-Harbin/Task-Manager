# 024 — 关联 Agent 的下拉框要列出全部 Agent（含不可用的）

- 日期：2026-10-28
- 状态：已实现

## 背景

新建任务时，关联 Agent 的下拉框里找不到某个 Agent —— 因为它当前是「不可用」状态。
下拉的数据源 `candidateAgents()` 只筛 `available` 的，唯一的例外是「这个任务**已经**关联了它」，
所以只有在任务详情里编辑旧任务时才看得见。新建任务时 `agentId` 还是空的，走不到那个例外。

用户的要求：**不管这个 Agent 可不可用，都要能在下拉框里选中。**

这条和「可用情况」的语义无关 —— 可用情况是「这个 Agent 现在能不能干活」，
不是「这个 Agent 存不存在、能不能被排进任务」。任务可以先排给一个暂时下线的 Agent，
等它恢复后直接开工，不该逼用户先把它改成可用、建完再改回去。

## 做什么

| # | 位置 | 行为 |
| --- | --- | --- |
| 1 | 新建任务弹窗 · 关联 Agent | 列出**全部** Agent，不可用的加「（不可用）」后缀 |
| 2 | 任务详情面板 · 关联 Agent | 同上（原本靠「已关联特例」才显示，现在天然涵盖） |
| 3 | 排序 | 不变 —— 仍按 Agent 列表的顺序，不做「可用的排前面」这类重排 |
| 4 | 「不关联」 | 保留为第一项，不受影响 |

后缀「（不可用）」在模板里**本来就有**（`{{ agent.available ? '' : '（不可用）' }}`），
这次只把数据源放开，模板一个字没动。

## 不做什么

- **不改「可用/不可用」的判定与自动恢复规则**（手动维护 + 到点自动恢复 + 系统通知，见 outline 3.4）。
- **不在服务端加可用性校验**。`validateLocked` 只校验「Agent 存在」，本来就不校验可用性；
  这次补一条 Go 测试把它固定下来，防止以后有人顺手加个 `Available` 判断把功能锁死。
- **不在 Agent 列表页做任何改动**（排序、标签、展开区都不动）。
- **不隐藏不可用项**、不做置灰不可点击 —— 用户要的就是能选。

## 验收标准

1. 新建任务，任务类型选「代码」，关联 Agent 下拉的选项数 = **全部 Agent 数 + 1**（「不关联」）。
2. 那个不可用的 Agent 在列表里，文字带「（不可用）」后缀；可用的条目不带后缀。
3. 能选中不可用的那个，并且提交后服务端收到的 `agentId` 就是它。
4. 刷新后，新任务的详情面板里「关联 Agent」显示为该项（带「（不可用）」），不被重置成「不关联」。
5. 详情面板的下拉同样列出全部 Agent（第 2 处调用点）。
6. 对照组：把「只列可用项」的输出还原到 DOM 上，上面 1–5 必须失败。
7. 服务端：`CreateTask` / `UpdateTask` 接受指向不可用 Agent 的 `agentId`（Go 测试固定）。
8. 不影响 019–023 的滚动/贴合读数。

## 影响面

- 前端：`frontend/src/App.vue`（`candidateAgents()` 去掉过滤与特例，两处调用点改签名）。
- 后端：无代码改动，只加测试 `TestUnavailableAgentStillAttachesToTask`。
- 数据迁移：无。
