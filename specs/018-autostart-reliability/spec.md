# 018 开机自启：改直写注册表 + 启动自愈

## 背景（现象与排查）

用户反馈「设置了开机自动启动，但并没有开机自启」。实测：

- 数据文件 `task-manager-data.json` 里 `settings.autoStart` 已是 `true`（说明设置**保存成功**）；
- 但 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里**没有 `Task Manager` 这一项**；
- 已排除的其它位置：`HKCU\...\WOW6432Node\...\Run`（32 位视图）、`RunOnce`、`StartupFolder`、
  `HKLM` 的 Run 键，以及 `StartupApproved`（无禁用记录）——即注册表项**从未写入成功**。

设置存下来了、注册表却没写进去，二者矛盾。现有实现（`app.go` 的 `setAutoStart`）用
`exec.Command("reg", "add", ...).Run()` 写注册表，它有三个确定的问题：

1. **`Run()` 丢弃 stdout/stderr** —— 失败时只剩 `exit status 1`，看不出原因；
2. **写入后不回读校验** —— 若调用方（安全软件、组策略）放行了调用却不落盘，程序无从察觉，
   于是「设置显示已开、实际从未生效」这种最难排查的状态成为可能；
3. **`setAutoStart(false)` 把删除失败吞成 `nil`**，取消自启也可能静默无效。

另外还有两个非功能性缺陷：

4. 从 GUI 进程启动 `reg.exe`（控制台程序）会让**控制台窗口闪一下** ——
   012 已在桌面通知上修过同类问题（`CREATE_NO_WINDOW`），这里漏了；
5. **exe 路径一变就失效**：注册表里存的是绝对路径，用户移动/重命名程序目录后，
   项还在但指向旧位置，开机时静默失败。

## 做什么

1. **改用 Windows 注册表 API 直接读写**（`golang.org/x/sys/windows/registry`），不再起 `reg.exe` 子进程。
2. **写入后立即回读校验**，值不一致就返回错误 —— 杜绝「静默成功」。
3. **删除失败不再吞掉**（键/值本来不存在的情况除外）。
4. **启动时自愈**：若设置里开着自启，则在每次启动时确保注册表项存在**且指向当前 exe 路径**；
   不一致就修正。这一条同时修掉「历史遗留的缺失项」和「移动 exe 后指向失效」两种情况。
5. 写注册表失败时，错误信息要具体（拒绝访问 / 未生效等），并如实上报到界面。

## 不做什么

- 不改 `settings.autoStart` 的存储方式与前端交互（仍是设置弹窗里的一个开关）。
- 不加「开机自启」之外的启动项类型（如计划任务、服务、启动文件夹快捷方式）。
- 不请求管理员权限：`HKCU` 项对当前用户可写，无需 UAC 提权。
- 不改 `UpdateSettings` 的失败语义（自启写入失败仍整体报错、不落盘），
  以保证「设置里的值 == 注册表的实际状态」这一不变量。

## 验收标准

1. 勾选自启并保存后，`HKCU\...\Run` 中出现 `Task Manager`，值为**带引号的当前 exe 绝对路径**。
2. 取消勾选并保存后，该项消失；若项本就不存在，保存仍成功（不报错）。
3. 注册表项被人为删除后重新启动程序，若设置里是开着，则该项被自动补回。
4. 注册表项指向旧路径时启动程序，该项被改写为当前 exe 路径。
5. 写入被拒绝/不生效时，界面显示可读的错误，而不是显示「设置已保存」。
6. 设置自启的过程不出现控制台黑框（不再启动任何子进程）。
7. `gofmt` / `go vet` / `go test ./...` 全过；新增测试不触碰真实用户的 `Task Manager` 注册表项。
