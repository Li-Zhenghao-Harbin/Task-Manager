# 003 即时保存 · 关联统一 · 重置通知

本规格修订 002 中与「任务关联 Agent」「Agent 关联项目」相关的模型定义，其余条款继续有效。

## 背景

002 交付后暴露三个问题：

1. **右侧面板必须手动保存**。任务详情、Agent 详情都要点【保存全部修改】才落盘，切换选中项就丢改动，与「右侧面板所见即所得」的预期不符。
2. **同一个关联存了两份，互不联通**。「Agent 关联项目」写 `AgentApp.ProjectIDs`，「任务关联 Agent」写 `Task.AgentID`，两条写入路径各自为政。实测存档：`Codex-GPT` 的关联项目里有 4 个代码任务，而这 4 个任务的 `agentId` 全为空 —— 于是 Agent 面板显示已关联，任务列表却显示未关联。
3. **重置到点恢复是静默的**。到点后状态自动变回可用，但用户没有任何感知，需要自己盯着列表。

## 做什么

### A. 右侧面板即时保存

- 任务详情面板与 Agent 详情面板的全部字段，修改后自动落盘，**移除两个面板上的保存按钮**。
- 连续输入做防抖（约 500ms），避免每敲一个字就写一次磁盘。
- 面板内显示保存状态：`正在保存…` / `已保存` / 未填完的提示；**校验不通过时不落盘**，只在面板内给出提示，不弹错误提示。
- 切换选中项、执行删除前，先把未落盘的修改冲刷掉，避免丢改动。

### B. 关系统一：任务侧为唯一事实来源

- 关系保持单值：**一个代码任务最多关联一个 Agent**。
- **唯一事实来源是 `Task.AgentID`**；`AgentApp.ProjectIDs` 降级为派生视图，恒等于「`agentId` 指向该 Agent 的代码任务集合」。
- 任一方向写入，另一方向立即同步：
  - 任务面板改「关联 Agent」→ 该任务归入新 Agent 的项目列表，并从旧 Agent 的列表中移除。
  - Agent 面板勾选「关联项目」→ 该任务的 `agentId` 指向本 Agent（原本属于其他 Agent 则转移）；取消勾选 → 清空该任务的 `agentId`。
- **启动与导入时做一次数据修复**：对 `agentId` 为空的代码任务，若某个 Agent 的项目列表包含它，则把它补记到该 Agent 名下；随后按任务重建所有 Agent 的项目列表。修复是幂等的。

### C. 重置到点通知

- 应用运行期间常驻检查（约 30s 一次）。某个不可用 Agent 到达下次重置时间时：自动恢复为可用 + 弹出 **Windows 系统通知**，通知内容包含「应用名-模型名」。
- 恢复并通知后，前端列表自动刷新，无需手动操作。
- 应用启动时同样检查一次，覆盖「关闭期间已到点」的情况，并同样发出通知。
- 通知投放失败**不影响**状态恢复与落盘；当前端不支持事件时，界面在下次读取时也会看到最新状态。

## 不做什么

- 不做多对多关联，一个任务仍然最多一个 Agent。
- 不做通知的设置项（开关、免打扰、历史记录）。
- 不引入新的持久化结构或独立轮询接口，仍沿用 Wails 绑定 + 随机事件。
- 不改动 Agent 应用的字段集合与校验规则（002 的定义继续有效）。

## 验收标准

1. 修改任务面板任一字段后不点任何按钮，等待约 0.5s，重启应用后修改仍在。
2. 任务面板与 Agent 面板均不再出现保存按钮，面板内可见保存状态。
3. 把任务名清空后不落盘，面板内出现提示，且不弹出错误提示浮层。
4. 切换选中的任务前输入的改动不会丢失（切走再切回，内容已落盘）。
5. 在 Agent 面板勾选一个代码任务为关联项目，任务列表中该任务随即显示该 Agent。
6. 在任务面板为某任务选择 Agent，Agent 面板该 Agent 的项目列表出现该任务。
7. 把任务类型由代码改为文档：任务关联被清空，且该任务从 Agent 的项目列表中消失。
8. 用 002 时期的旧存档（Agent 关联了任务、任务 `agentId` 为空）启动后，任务列表能显示对应 Agent。
9. 同一任务被两个 Agent 的项目列表同时包含时，以任务上的 `agentId` 为准，重建后的项目列表不重复。
10. 把某 Agent 设为不可用、重置时间设为 1 分钟后：到点后其状态自动变为可用，并收到一条 Windows 通知，通知中含「应用名-模型名」。
11. 应用关闭期间到点的 Agent，下次启动时恢复为可用并发出通知。
