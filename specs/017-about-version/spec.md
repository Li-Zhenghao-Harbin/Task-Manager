# 017 【关于】弹窗的版本号与构建配置同源

## 背景

016 把 exe 右键属性的元数据接到了 `wails.json` 的 `info` 块，但我们漏掉了界面这一侧：
【关于】弹窗里的「版本号」写死成了 `beta`，于是同一个程序在属性页显示 `1.0.0`、在关于弹窗显示 `beta`，
两个数字自相矛盾，而且升版本时必然漏改一处。

## 做什么

- 【关于】弹窗的「版本号」改为显示 `wails.json` 的 `info.productVersion`，格式 `x.x.x`。
- 取值链路走 Wails 绑定（后端读取 → 前端渲染），不在前端写构建期常量。
- 版本号只有一处事实来源：`wails.json`。改版本号只需改那一行。

## 不做什么

- 不改 exe 属性的生成机制（`build/windows/info.json` 模板 + winres，016 已完成）。
- 不改【关于】弹窗的「程序名」与「作者」两项，它们本轮仍是硬编码文案。
- 不引入版本比较、更新检查等能力。
- 不在前端做版本号格式化（`1.0.0.0` → `1.0.0` 之类的截断）；`wails.json` 里写什么就显示什么。

## 验收标准

1. `wails.json` 的 `info.productVersion` 为 `"1.0.0"` 时，弹窗「版本号」显示 `1.0.0`。
2. 改 `wails.json` 的版本号并重新构建后，弹窗显示的值随之变化，且**无需改动任何 `.vue` / `.go` 代码**。
3. 界面任何位置不再出现 `beta`。
4. 无 Wails 运行时的预览环境（纯浏览器打开 `dist`）不报错，版本号降级显示为 `—`。
5. Go 侧有测试钉住「返回值 == `wails.json` 里的值」与「格式为 `x.x.x`」。
