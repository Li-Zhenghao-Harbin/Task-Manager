# 009 · Prompt 卡片头部一行化

## 背景

008 把每条 prompt 卡片做成「上段左右两栏 + 下段底部右对齐删除」的两段结构。
实际用起来头部信息被拆到了两个角落（【Prompt N】在左上、【删除】在右下），
卡片高度也被左列撑高（`.prompt-body{align-items:stretch}` 要求左列与文本框等高）。

本次把卡片的操作区收敛成**一行头部**，文本框独占下方整行。

## 做什么

1. **每条 prompt 卡片的第一行是一条头部**，水平排布三个元素，顺序固定：
   - 左起第一个：【Prompt N】文案（N 为 1 起始的序号）；
   - 紧跟其后：【复制】按钮；
   - 同一行的最右端：【删除】按钮。
2. 【Prompt N】与【复制】**靠左对齐**，两者之间保持固定的小间距；
   【删除】**靠右对齐**（贴卡片内容区右边缘），与【复制】之间留出可伸展的空白。
3. 头部下方**换行**显示文本框，文本框**横向撑满**卡片内容区宽度；
   文本框的最小高度、可纵向拖拽（`resize:vertical`）、占位文案保持不变。
4. 三个元素的文案、颜色、点击行为全部不变：
   - 【复制】→ `copyPrompt(prompt)`（写系统剪贴板，空内容不写并提示）；
   - 【删除】→ `removePrompt(index)`（直接删除并落盘，无确认弹窗）；
   - 【Prompt N】是纯文案，不可点击。
5. 卡片本身的内边距、圆角、边框、背景，以及卡片之间的间距，沿用 008 的观感不变。

## 不做什么

- 不改 prompt 的数据结构、接口、生命周期（沿用 005）。
- 不改 Prompt 独立视图的整体版式（标题行、返回按钮、右上角【添加 Prompt】、栅格容器）。
- 不改 Agent 详情面板的布局（沿用 007）。
- 不新增任何交互（例如不把【Prompt N】做成可点击的折叠开关）。

## 验收标准

1. 每条 prompt 卡片里，【Prompt N】与【复制】的左边缘在同一竖直线上，且两者垂直中心齐平。
2. 【删除】与【Prompt N】/【复制】处于同一行（垂直区间重叠），且其**右边缘贴卡片内容区右边缘**。
3. `删除.left - 复制.right` 明显大于 0（两者之间有留白，不再相邻）。
4. 文本框的垂直位置**完全在头部下方**（`textarea.top ≥ head.bottom`），且宽度等于卡片内容区宽度。
5. 点击【复制】：提示文案正确、剪贴板拿到该条 prompt 全文、且**不触发保存**。
6. 点击【删除】：该条 prompt 立即从列表消失、调用一次保存接口、提交剩余条目。
7. `gofmt` / `go vet` / `go test ./...` / `vue-tsc` / `wails build` 全部通过，无回归。
