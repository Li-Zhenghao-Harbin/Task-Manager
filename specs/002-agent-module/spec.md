# 002 Agent 模块功能规格

## 背景

任务管理器已具备「任务 / 产出 / 单位」三块能力。实际工作中，一个代码任务往往由某个 Agent 应用（应用 + 模型 + 所属代码项目）来执行，而 Agent 的额度耗尽后需要等待重置。

本规格新增 **Agent 模块**，用于登记可用的 Agent 应用，并允许代码任务关联其中一个。

## 术语

| 术语 | 含义 |
| --- | --- |
| Agent 应用 | 一条登记记录，由「应用名 + 模型名」标识，可关联若干代码项目 |
| 关联项目 | 复用现有任务：**任务类型为「代码」的任务** 即为可选项目，不做独立项目实体 |
| 可用情况 | 该 Agent 应用当前是否可用（手动维护） |
| 下次重置时间 | 不可用时预计恢复可用的时间点，精确到分钟 |

## 用户故事

1. 作为用户，我可以在左侧菜单进入【Agent → Agent应用】，看到已登记的 Agent 应用列表，每条以「应用名-模型名」显示。
2. 作为用户，我可以新增 Agent 应用，填写应用名、模型名、关联项目（可多选，仅限代码任务）、可用情况、下次重置时间。
3. 作为用户，我可以修改或删除已有 Agent 应用。
4. 作为用户，当 Agent 不可用且设置了下次重置时间，到点后它应自动恢复为可用。
5. 作为用户，在创建或编辑一个**代码任务**时，可以为其关联一个可用的 Agent 应用。
6. 作为用户，我在任务列表中能看出某个代码任务关联了哪个 Agent。

## 做什么

### A. 左侧菜单

- 新增一级分组 **Agent**，其下包含子菜单 **Agent应用**。
- 「Agent应用」条目右侧显示已登记的 Agent 应用数量。
- 分组标题与子条目在视觉上呈现层级缩进，后续可在该分组下继续扩展子模块。

### B. Agent 应用字段

| 字段 | 类型/格式 | 必填 | 说明 |
| --- | --- | --- | --- |
| 应用名 | 文本 | 是 | 去除首尾空格后不得为空 |
| 模型名 | 自由文本 | 是 | 不做枚举限制，用户自行填写 |
| 关联项目 | 列表（多选） | 否 | 候选项为**任务类型 = 代码**的任务；存任务 ID |
| 可用情况 | 布尔 | 是 | 手动设置，新建默认「可用」 |
| 下次重置时间 | 日期时间，精确到分钟 | 否 | 仅在不可用时才有意义 |

### C. 可用情况与自动重置

- 可用情况由用户手动切换。
- 当「可用情况 = 不可用」且设置了「下次重置时间」时，**到达该时间点后自动恢复为可用，并清空下次重置时间**。
- 自动重置的判定发生在读取列表时（含应用启动），因此无需应用常驻运行也能保证到点恢复。

### D. 列表展示

- 每条记录主标题为「应用名-模型名」，例如 `Claude Code-Claude Opus 4.1`。
- 同时展示可用情况徽标、下次重置时间、关联项目名称。
- 点击记录在右侧详情面板中编辑；右侧面板在 Agent 分区下展示 Agent 应用的编辑表单。
- 支持删除（二次确认）。

### E. 任务关联 Agent

- 任务详情面板与「创建任务」表单中，**仅当任务类型为「代码」时**显示「关联 Agent」字段。
- 该字段为**单选**下拉，候选项为**当前可用**的 Agent 应用，显示为「应用名-模型名」。
- 允许留空（不关联）。
- 若任务原本关联的 Agent 变成不可用，该 Agent 仍出现在候选项中并标注「不可用」，避免保存时静默丢失关联。
- 任务类型从「代码」改为其他类型时，任务上的 Agent 关联被自动清空。

## 不做什么

- 不新增独立的「项目」实体，不新增项目类型字段；「关联项目」直接复用任务类型为代码的任务。
- 不限制模型名的取值范围，不维护模型预设清单。
- 不做配额/用量的自动探测，可用情况完全由用户手动维护（仅重置时间到点会自动恢复）。
- 不记录 Agent 调用的历史流水，不与任何外部 Agent 平台通信。
- 一个任务最多关联一个 Agent，不做多对多。

## 验收标准

1. 左侧菜单出现 Agent 分组与 Agent应用子条目，条目旁数量等于已登记记录数。
2. 可新增 Agent 应用；应用名或模型名为空时被拒绝并提示。
3. 关联项目候选中**只出现任务类型为代码的任务**；提交一个非代码任务 ID 会被后端拒绝。
4. 新增后在列表中显示为「应用名-模型名」。
5. 可将某 Agent 设为不可用并设置下次重置时间（精确到分钟）；把重置时间设为过去后再刷新列表，该 Agent 自动恢复为可用且重置时间清空。
6. 编辑任务时，只有「代码」类型才出现「关联 Agent」字段；下拉中只出现可用的 Agent（外加当前已关联但已不可用的那一个）。
7. 代码任务可成功关联并保存；任务列表行中能看到所关联的「应用名-模型名」。
8. 删除 Agent 应用后，原本关联该 Agent 的任务其关联字段被清空。
9. 删除一个被 Agent 关联的代码任务后，该任务 ID 从 Agent 的关联项目列表中移除。
10. 所有数据重启应用后仍可读取。
