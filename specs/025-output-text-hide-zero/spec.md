# 025 — 列表里的产出摘要只列非零项

- 日期：2026-10-29
- 状态：已实现

## 背景

【产出概览】切到【代码】/【文档】/【实施】后，「对应任务」列表每行右侧有一小段产出摘要：

```
Clou BusinessOpportunityGrabber     新增功能 0 | 修改功能 0 | 应用程序 1
ClouESP 8.0                         新增功能 0 | 修改功能 0 | 应用程序 0
```

值为 0 的项占了三分之二的篇幅却不携带信息，整行的重点（应用程序 1）反而被挤到末尾。
用户要求：**xx 为 0 的那一段整段不显示**（新增功能 / 修改功能 / 应用程序 / 新增文档 / 修改文档 / Skills 同理）。

## 做什么

| # | 场景 | 行为 |
| --- | --- | --- |
| 1 | 部分字段为 0 | 只列非零项，分隔符随之减少 —— `应用程序 1`、`修改功能 1` |
| 2 | 全部字段为 0 | 整段摘要不渲染（连 `<em>` 元素都没有，右侧不留空占位） |
| 3 | 全部字段非 0 | 与改动前完全一致 |
| 4 | 【实施】筛选 | 只有一个字段，值为 1 时显示 `实施 1`；为 0 时整段不显示 |
| 5 | 顺序 | 仍按 `typeKeys` 的原顺序，不因裁剪而重排 |

## 不做什么

- **不动右侧详情面板的产出输入框**。那里必须全量显示，否则值为 0 的字段隐藏后就再也改不回去了
  （只能靠改数据文件）。这条已写进验证判据，防止以后有人把 `v-if` 顺手加到面板上。
- **不动 KPI 卡片、饼图、左侧菜单计数**。它们统计的是总量，0 也是有效读数。
- **不隐藏整行**。全零的任务仍显示在列表里、仍可点击（它是一条真实任务）。
- 不改数据、不加迁移。

## 验收标准

1. 【代码】筛选：`Meter Group Management显示优化` 显示 `修改功能 1`，不再是 `新增功能 0 | 修改功能 1 | 应用程序 0`。
2. 【代码】筛选：`ClouESP 8.0` / `ClouESP Docker部署`（全零）整行没有摘要，且**没有** `<em>` 元素。
3. 【文档】筛选：`ClouESP业务文档` 显示 `新增文档 23`；`Go+Wails项目添加图标Skills` 显示 `Skills 1`。
4. 【实施】筛选：`测试电表上线` 显示 `实施 1`。
5. 每行摘要与「按真值数据算出的非零项文本」逐行一致（顺序、空格、分隔符都要一致）。
6. 摘要里不出现 `X 0`；不出现空段、首尾残留的 `|`。
7. 详情面板打开同一任务时，数量字段仍是 3 个（0 的字段也在）。
8. 对照组（把旧的全量文本还原到 DOM）上述判据必须失败。
9. 019–024 的所有读数不变。

## 影响面

- 前端：`frontend/src/App.vue` —— `taskOutputText()` 加一层过滤，模板给 `<em>` 加 `v-if`。
- 后端 / 数据：无。
